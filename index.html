Security is a foundational element that I embedded within my development workflow as it is much more difficult and suboptimal to implement after an application is developed. Not only this, but I am dedicated to protecting user privacy and preventing vulnerabilities that can jeopardize not only users, but code integrity too. My practices include mitigating SQL injections through parameterized database queries, implementing strict data validation protocols, and enforcing dynamic runtime permission checks for hardware features while employing industry standard cryptographic hashing algorithms (such as BCrypt) to protect user credentials.

The centerpiece of my portfolio is my Android based mobile inventory tracking application called “TrakTrak”. This artifact represents a demonstration of my multi-faceted talents in computer science, as it shows my enhancement of a full stack application that is elevated to meet professional standards. The architecture of this application was modernized by introducing a Singleton pattern to manage the database connections across concurrent activities. I offloaded heavy disk I/O operations from the main UI thread to asynchronous background threads using single thread executors. The user interface was modularized using a custom InventoryAdapter and a reusable ViewHolder pattern to handle dynamic view lifecycle bindings. To optimize the data and UI synchronization, I integrated a dual layered collection strategy inside DataActivity. By pairing an ArrayList with a tracking HashMap, the application avoids redundant database queries when verifying item existence or retrieving records in memory. This creates a responsive and lag free user experience. The underlying data layer was hardened against modern threat vectors. In DataBase helper, manual string concatenation was replaced with parameterized SQLite queries and compiled ContentValues to block SQL injection attacks. Plaintext user authentication was replaced with stronger password security using BCrypt salting and hashing. Lastly, the external communication pathways in SmsActivity were locked down by enforcing runtime permission checks to protect user privacy and hardware resources. This artifact from my CS 360 mobile development course showcases a combined and complete software enhancement, demonstrating my ability to deliver safe, efficient, and improved software solutions.

1. Software Design and Engineering

Read the Narrative

This artifact was selected for my portfolio because it is a full stack inventory tracking application. It shows my ability to develop a complete and functional software system with a mobile interface, data persistence, and foundational security. Enhancing this artifact showcases that I can analyze legacy codebases and diagnose architectural defects to refactor so that it can meet higher standards in scalability, security, and stability. DatabaseHelper was refactored into a thread safe singleton pattern, using double checked locking that demonstrates my understanding of memory management and object lifecycle controls within the Android framework. I had hardcoded activity casting within InventoryAdapter, so I replaced it with a lambda callback interface (runnable). This demonstrates the ability to design decouple and reusable interface components. Along with this, I parameterized raw database statements, math floor boundaries, and runtime input validation to show that I can implement defense mechanisms that can preserve system data integrity and fight against code exploitation. I provided database connection consolidation, architectural decoupling, and made resource management more robust and enhanced security.

2. Algorithms and Data Structures

Read the Narrative

I selected this as an artifact for my ePortfolio as I feel it can incorporate all of the milestones necessary to show my growth and complete the capstone course. It’s a multifaceted design that is ultimately unoptimized and can be improved in the software area, data structure and algorithm, and database. This will showcase my skills in understanding legacy code and improving the function. I implemented a multi index memory cache layer and combined a hash table with a self-balancing red-black binary search tree to handle alphabetical sorting. I cut down processing time by replacing the linear search loop over a ArrayList with the dual index hash tree model. I enforced variable immutability inside InventoryItem using the final keyword which assists with code quality standards. I fixed database query parameters to isolate user account data as to not cross contaminate data. Then I had decoupled SQLite’s auto increment keys from the user interface and implemented a runtime sequential loop which makes it so that profiles track their inventories starting a 1 (which fixed a previous issue that the starting inventory number was 2 or a continuation of another database’s list).

3. Databases

Read the Narrative

I included this item in my portfolio as it is a full stack mobile application with real functionality, not only that, but it encompasses all of the milestones and has a great foundation to improve upon to show my growth. With this milestone, I found that the codebase has some technical debt and performance issues along with compromised safety. It relied on a structural runtime sorting collection within the view controller lifecycle, so I had changed the relational table queries to request sorted indices through an ORDER BY NAME ASC execution path. This reduced memory consumption on the host device. I also replaced plaintext login credentials with routing registration keys through a BCrypt cryptographic algorithm. Now the passwords won’t touch the database disk array without hashing.
